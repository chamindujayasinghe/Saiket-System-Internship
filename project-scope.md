## 1. Purpose

This document sets the scope of the SaiKet Systems Full Stack Development internship. It covers six tasks that move step by step from static front-end pages to a complete full-stack application, plus the required video submission on LinkedIn.

Each task is a separate deliverable. The brief says: *"make a separate file of each level"*, so every task lives in its own folder.

---

## 2. Objectives

- Show core front-end skills: semantic HTML, responsive CSS, vanilla JavaScript, and a utility/component CSS framework (Bootstrap or Tailwind).
- Show working knowledge of a modern front-end framework (React.js or Angular).
- Design and build a RESTful back-end with Node.js and Express.
- Store data in a relational database (MySQL or PostgreSQL) using SQL.
- Connect front-end, back-end, and database into one working full-stack application.
- Present the finished work professionally on LinkedIn.

## 4. Task Breakdown

### Task 1 — Static Portfolio Website with a Theme

**Goal:** Build a themed personal portfolio site.

**In scope**
- Homepage (hero/intro, about, navigation).
- **"Projects"** section with placeholder project cards.
- **Contact form** with client-side **JavaScript validation** (required fields, email format, error/success feedback).
- Styling with **Bootstrap or Tailwind**.
- Responsive, visually appealing layout on mobile, tablet, and desktop.

**Skills:** HTML, CSS, JavaScript

**Acceptance criteria**
- [ ] Homepage, Projects section, and Contact section are present and reachable from the navigation.
- [ ] Contact form blocks invalid submissions and shows clear validation messages.
- [ ] Layout works at mobile (≤576px), tablet (~768px), and desktop (≥1200px) widths.
- [ ] A consistent theme (colours, typography) is used throughout.

---

### Task 2 — Responsive Web Page (e.g., E-Commerce Landing Page)

**Goal:** Design a responsive marketing/landing page, such as one for an e-commerce store.

**In scope**
- Landing page built with HTML, CSS, and **Bootstrap/Tailwind**.
- Typical e-commerce sections, e.g. hero banner, featured products, categories, testimonials, newsletter signup, footer.
- **Interactive features in vanilla JavaScript**, e.g. form validation, a toggle button (mobile menu, dark/light mode), or add-to-cart feedback.

**Skills:** HTML, CSS, basic understanding of e-commerce concepts

**Acceptance criteria**
- [ ] Page is fully responsive with no horizontal scrolling on small screens.
- [ ] At least one interactive feature is built in vanilla JavaScript (no jQuery or framework).
- [ ] The content and layout clearly communicate an e-commerce purpose.

---

### Task 3 — Front-End Framework Basics (To-Do List App)

**Goal:** Learn the core features of React.js or Angular by building a small to-do list app.

**In scope**
- Users can **add**, **edit**, and **delete** tasks.
- Show the framework's core concepts:
  - *React:* components, props, state (`useState`), event handling, list rendering with keys.
  - *Angular:* components, data binding, directives (`*ngFor`, `*ngIf`), services, event binding.
- Clean, usable UI.

**Out of scope (optional extras):** mark-as-complete, filtering, `localStorage` persistence.

**Skills:** Front-end framework basics

**Acceptance criteria**
- [ ] Adding a task updates the list immediately.
- [ ] Editing a task changes its text in place.
- [ ] Deleting a task removes it from the list.
- [ ] Empty or whitespace-only tasks are rejected.

---

### Task 4 — Basic REST API (User Entity)

**Goal:** Build a REST API with Node.js and Express offering CRUD operations on a **User** entity.

**User entity**

| Field | Type | Notes |
|---|---|---|
| `id` | integer / UUID | Generated by the server |
| `name` | string | Required |
| `email` | string | Required, valid format, unique |
| `age` | integer | Optional or required, must be a positive number |

**Endpoints**

| Method | Route | Description |
|---|---|---|
| `GET` | `/api/users` | List all users |
| `GET` | `/api/users/:id` | Get one user |
| `POST` | `/api/users` | Create a user |
| `PUT` | `/api/users/:id` | Update a user |
| `DELETE` | `/api/users/:id` | Delete a user |

**In scope**
- JSON request and response handling (`express.json()`).
- Input validation and correct HTTP status codes (`200`, `201`, `400`, `404`, `500`).
- Data storage in memory (a database comes in Task 5).
- **Testing every endpoint with Postman** (exported collection included).

**Skills:** Node.js basics, REST API design, Express, JSON handling, Postman testing

**Acceptance criteria**
- [ ] All five endpoints work and return JSON.
- [ ] Invalid input returns `400` with an error message; unknown IDs return `404`.
- [ ] A Postman collection covering every endpoint is included in the task folder.

---

### Task 5 — Database Integration

**Goal:** Connect the Task 4 API to **MySQL or PostgreSQL** so user data is stored permanently.

**In scope**
- Database and `users` table schema (SQL script included, e.g. `schema.sql`).
- Database connection from Express (e.g. `mysql2` or `pg`), with credentials kept in a `.env` file.
- Replace in-memory storage with **SQL queries** for every CRUD endpoint:
  - `SELECT`, `INSERT`, `UPDATE`, `DELETE`
- **Parameterised queries** to prevent SQL injection.
- Handle database errors (e.g. duplicate email).

**Skills:** Basic SQL, database connection, API integration, Express basics

**Acceptance criteria**
- [ ] Data is still there after the server restarts.
- [ ] All endpoints read from and write to the database.
- [ ] The schema script creates the table from scratch.
- [ ] Postman tests from Task 4 still pass against the database-backed API.

---

### Task 6 — Full Stack Application (User Management System)

**Goal:** Combine the front-end (Task 3 framework) with the back-end and database (Tasks 4–5) into a **User Management System**.

**Core features**
- **Create** a user profile (form with validation).
- **View** profiles (list view and detail view), with data coming from the database.
- **Update** a profile (pre-filled edit form).
- **Delete** a profile (with a confirmation step).

**In scope**
- Front-end calls the REST API (`fetch` / Axios / Angular `HttpClient`).
- Loading, empty, and error states in the UI.
- CORS set up on the API.
- Responsive UI.

**Optional (extra practice):** Login authentication (e.g. JWT or session-based, with hashed passwords).

**Skills:** Basics of full stack development

**Acceptance criteria**
- [ ] Every CRUD action in the UI is saved to the database and shown again on reload.
- [ ] The front-end shows only real data from the back-end (no hard-coded users).
- [ ] The app runs locally by following the README setup steps.
